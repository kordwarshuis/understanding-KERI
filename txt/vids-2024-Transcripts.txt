This is an introduction to KERI, the Key Event Receipt Infrastructure. My name is Samuel Smith and
I am the inventor of KERI. The reason I invented KERI is because the internet is broken and I
wanted to solve it. And so the problem that KERI solves is called the universal secure attribution
problem. Okay, what do we mean by universal secure attribution problem? Well, universal means
everywhere.
We want it to be solved everywhere. And secure means do it in a way that can't be hacked or forged
or impersonated or attacked in the normal way that we get attacked on the internet. Attribution means
assigning a communication to its source. We want to attribute where something came from to its source.
We know who's sending it to us. And so the problem is, how do we do that everywhere on the internet in
a secure way so that we know who's sending us information? So that doesn't mean we want to enable
anybody to track everybody's conversations. We want to do it in a privacy protecting way. So that poses
additional challenges. But first we have to get the security down. Many people approach this problem and
they sacrifice security. And if you sacrifice the security, then you don't have privacy either. So, what we
want to do is solve all of these problems at the same time in a very integrated, elegant, simple way. Let's
talk about what it means. Secure attribution is another way of saying we want to establish the authorship
of data, any and all data sent over the internet, any and all documents, things like credentials, entitle‐
ments, authorizations. We want to be able to say that we can securely attribute who's doing what in a
privacy-preserving way. And I keep saying privacy because I don't want to give the false impression that
we're trying to build this universal tracking system. The hard problem is to be able to do this all in a way
that keeps confidentiality and privacy along with secure attribution.
That's always been the hard problem. So to restate, the problem is we want to have verifiable secure
attribution of any communications to its source. Now I added the word verifiable. What does verifiable
mean? It means that if we're receiving information, we need some way to verify where it came from.
When I say verify, it means in a cryptographic sense. It means doing it without having to trust any third
party. I don't want to have to trust somebody else to verify what somebody that I want to communicate
with in a private confidential way says. I need to be able to do it by myself. If I have to trust someone,
then the security of whoever I'm trusting now becomes something I have to worry about. And that is a
problem.
Another way of looking at secure attribution is to say that we want to have provenance of any data by
anyone, to anyone, from anyone. And so a way we can describe that is as authentic data. And then we
want authentic data provenance.
Authentic has two meanings. It means like true to yourself, like you're being authentic. That's not the
meaning of authentic we're using here. We're meaning authentic as you can attribute it to its source.
Who painted that painting is an authentic painting, right? As opposed to when something's not authen‐
tic. It means it was forged or somebody was impersonated. Somebody sends you information and they
say it came from Joe when it really came from Sue. And so the whole problem is back to the same thing.
We need to securely attribute the source of information. So what do I mean by provenance? We often
hear the term provenance when we talk about like a painting, like fine art, right? Was it painted by
Rembrandt? And how do you know it was painted by Rembrandt? Well, one way that you would prove‐
nance it is that you would establish a chain of custody of that painting from Rembrandt to whoever
Rembrandt sold or gave the painting to whoever sold or gave the painting and so on. And if you can fol‐
low that chain of custody to the present owner or holder of that painting, then you can say, yeah, it came
